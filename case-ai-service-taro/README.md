# AI-сервис «Аметистовая жаба» (Системная аналитика)

Это проект по проектированию веб-сервиса, который генерирует персональные AI-толкования раскладов Таро на базе YandexGPT. 

## 🎯 Моя роль и задачи в проекте

**Роль:** Системный аналитик / Solution Architect.

**Что было сделано:**
*   Сформированы **User Stories** и сценарии использования (Use Cases) для двух ролей: Пользователь и Администратор.
*   Спроектирована **архитектура системы**: FastAPI, PostgreSQL, Celery, Redis, интеграция с ЮKassa, YandexGPT и Unisender Go.
*   Разработана **модель данных (PostgreSQL)** с учетом мягкого удаления (Soft Delete), партиционирования логов и хранения JSONB-структур.
*   Составлена **OpenAPI 3.1 спецификация** с едиными форматами ошибок, пагинацией и строгой валидацией (Mass Assignment Protection).
*   Описаны **State Machine** (жизненный цикл задач генерации) и схемы последовательностей (UML Sequence Diagrams).
*   Проработаны **нефункциональные требования (НФТ):** отказоустойчивость (RTO/RPO), сценарии деградации при падении Redis/PostgreSQL, Rate Limiting и безопасность (OWASP).

## 💡 Ключевые архитектурные вызовы, которые я решила

В ходе проектирования (и двух итераций строгого аудита) были найдены и устранены сложные архитектурные проблемы:

1.  **Паттерн Transactional Outbox:** Для гарантированной постановки задач в очередь (чтобы не терять оплаченные заказы при падении Redis) реализована запись в `outbox_events` в одной транзакции с обновлением статуса платежа.
2.  **Защита от Race Conditions (Очередь):** Внедрено «резервирование слотов» через Redis (`INCR/DECR`), чтобы пользователи не оплачивали услугу, если очередь гарантированно переполнена.
3.  **Защита от дублирующих оплат:** Обработчик вебхуков ЮKassa спроектирован так, чтобы при повторной оплате уже сгенерированного расклада не тратить токены нейросети, а фиксировать флаг `possible_duplicate_payment` для ручного возврата средств администратором.
4.  **Асинхронность и лимиты YandexGPT:** Спроектирована приоритизированная очередь задач (Celery) с учетом ограничения модели в 1 поток. Платные запросы имеют приоритет 9, бесплатные — 1. Рассчитана математика ETA (времени ожидания).
5.  **Юридическая безопасность (152-ФЗ и 422-ФЗ):** Спроектирован механизм автоматической анонимизации email через 12 месяцев, при этом финансовые данные в таблице `payments` хранятся бессрочно для налоговой. Реализована защита от XSS при рендеринге Markdown (юридические документы) и маскирование PII в логах.
